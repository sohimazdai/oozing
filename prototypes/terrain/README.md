# Рабочий образец генератора местности

Это исполняемый эталон нескольких правил будущего генератора Oozing. Он создаёт **один конечный водосбор 3,2 × 3,2 км**: 64 сектора по 400 × 400 м, общая сетка 129 × 129 отсчётов с шагом 25 м. Код использует только стандартную библиотеку Python 3 и не привязан к игровому движку. На macOS команды выполняются в Terminal при наличии Python 3.

Это диагностическая карта, не изображение будущего качества игры. Псевдобесконечный мир, готовая 3D-сцена, коллизии, разрушение, персонажи, переносимые земные фрагменты, пещеры и реальное движение воды **здесь ещё не реализованы**. Полную архитектуру описывает [документ генерации](../../docs/09-world-generation.md).

## Запуск

Из корня проекта:

```sh
python3 -B prototypes/terrain/generate.py --seed 731
python3 -B -m unittest discover -s prototypes/terrain -p 'test_*.py' -v
```

Для другого варианта:

```sh
python3 -B prototypes/terrain/generate.py --seed 732 --output /tmp/oozing-terrain-732
```

Без `--output` результат сохраняется в `outputs/seed-<число>` рядом с программой. Повторный запуск с тем же seed и версией алгоритма перезаписывает этот набор воспроизводимыми данными. Создание конкретного снимка ниже проверено; производительность будущей игры из этого не следует.

## Что получается

- [preview.svg](outputs/seed-731/preview.svg) — автономная карта с подписями: высоты, биомы, вода. PNG встроены внутрь SVG; сеть и соседние файлы ему не нужны.
- [preview.png](outputs/seed-731/preview.png) — те же три панели без подписей, для быстрой проверки изображения.
- [terrain.json](outputs/seed-731/terrain.json) — параметры, краткая статистика и все поля сетки. Это промежуточные данные для проверки, не формат сохранения игры.

В каждой панели показана **одна и та же местность**. Север сверху. Тёмные линии обозначают сектора 400 × 400 м. Светлая бирюза — реки, более тёмная синяя вода — заполненные впадины. Ширина цветной полосы обусловлена шагом сетки; она не задаёт реальную ширину русла. При смешении биомов цвет тоже смешивается, поэтому опушка не рисуется жёсткой границей клетки.

## Порядок расчёта

1. `raw_height(seed, x, z)` читает глобальные координаты. Низкочастотный шум задаёт крупные массы; небольшая деформация координат и более мелкий шум добавляют нерегулярность. Аналитические вершины, извилистая долина, узкое ущелье и локальные ложбины делают рельеф осмысленным уже на этом масштабе. Они преднамеренно задают форму **одного** испытательного водосбора.
2. Выбирается единственный выход — самая низкая точка южного края. Все остальные внешние края условно закрыты. Это известная граница эксперимента, не решение стыковки соседних водосборов.
3. `priority_flood` обходит сетку от выхода через очередь приоритетов. Впадины заполняются до уровней стока. Каждая точка получает уже обработанного нижнего соседа. Равные приоритеты разрешаются индексом глобальной точки. Добавка 5 мм на ребро делает направление однозначным и исключает циклы; это численный приём, **не физически наклонённая поверхность озера**.
4. Пространственное поле осадков накапливается по полученному дереву стока. Значения — условные единицы на отсчёт, не м³/с. Выше порога возникают связанные реки; заполнения глубже 1,5 м показаны как озёра. На речных отсчётах немного понижается дно. Профиль водной поверхности монотонно спускается к выходу.
5. От воды вычисляется расстояние. Влажность зависит от него и крупного климатического поля; условная температура — от высоты и другого поля. Уклон и высота добавляют каменистость. Для степи, высокой травы, леса, поймы и камней рассчитываются нормализованные мягкие веса. Это демонстрационные среды, не окончательный каталог биомов Кромы.
6. `extract_sector(world, x, z)` только выбирает данные общей сетки. Включённые края соседних секторов совпадают по высоте, нормали, воде, весам биомов и ID. Нормали рассчитаны до разрезания на сектора с настоящими соседями глобальной сетки.

Это поле высот, поэтому нависание, вход в пещеру и подземный проход оно не выражает. Для них нужен отдельный трёхмерный слой. Ущелья и ложбины здесь видны как формы поверхности; процедурные пещеры из этого автоматически не возникают. Очень высокая трава обозначена весом среды; отдельных стеблей и деревьев нет.

## Контракт данных

В JSON `grid` содержит плоские массивы: индекс `i = z × side_samples + x`; координаты в метрах — `(x × spacing_m, z × spacing_m)`. Высота — вертикальная ось Y. Нормаль имеет порядок `[nx, ny, nz]`. У каждого массива 16 641 элемент; `biome_weights` и `normal` содержат вложенные списки.

| Поле | Значение |
| --- | --- |
| `height_m` | Поверхность грунта после минимального углубления речных точек |
| `routing_height_m` | Численный уровень для направленного стока; не поверхность воды в сухой точке |
| `water_surface_m`, `water_depth_m` | Поверхность воды или `null`; глубина, на суше 0 |
| `downstream` | Индекс следующей точки по стоку, `-1` только у выхода |
| `flow_units`, `river`, `lake` | Накопленный условный сток и маски воды |
| `moisture`, `temperature` | Безразмерные климатические параметры 0–1 |
| `biome_weights`, `biome` | Мягкие веса и индекс наибольшего веса в `biome_names` |
| `normal` | Нормализованная нормаль глобальной поверхности |

Для ID используется адрес из версии генератора, seed, типа и координат. Изменение порядка запросов или добавление другого объекта не сдвигает последовательность случайностей. JSON округлён до шести знаков после запятой; вычисления и проверки выполняются до округления. Битовая идентичность на иных реализациях математической библиотеки не обещается: будущий движок должен зафиксировать численную спецификацию.

## Что проверяется

Тесты подтверждают воспроизводимость seed, изменение мира при смене seed, независимость ID от `PYTHONHASHSEED`, совпадение секторов при прямом, обратном и перемешанном извлечении, совпадение **всех** общих образцов, отсутствие циклов, достижение выхода каждым стоком, сохранение реки до выхода, отсутствие подъёмов её водной поверхности, положительную глубину, баланс условных осадков и нормализацию полей.

Эти проверки относятся к данным. Они не доказывают бесшовность физики, соединение навигации, кадры в секунду, корректность LOD или сохранение разрушений. До большого мира нужно реализовать и проверить контракт соседних водосборов, масштабируемое хранение, трёхмерную геометрию, физику и потоковую загрузку в выбранном движке. Для финального искусства также потребуются направленная эрозия, скальные формы, береговые профили, растительность и авторская проверка композиции с игровой камеры.
